# 演示与测试场景

本文记录预设设计，尚未实现。房间投递、逐帖限长及回执见 [MVP 设计](design.md)。

## 预设 01：双模型辩论

**议题：命令行工具请求超时，应默认自动重试吗？** 题目不需要联网或改项目文件；双方既可以质疑对方对失败原因的假设，也可以提出具体反例、改变结论。每条 Agent 发言最多 **100 显示宽度**；详细论证可以写成临时 Markdown 文件，在群里贴其绝对路径。

### 演示的操作

1. 用户在 OpenChamber 选择「双模型辩论」，为 A、B 各选一个本机可用模型，确认后创建一个房间和两个独立会话。默认不锁定供应商，也不在创建时执行模型；模型缺失时由用户重新选择。
2. 用户点击开始。预设发布一条人类发起的公开议题作为首帖。A 的初始立场是「可以默认重试」，B 的初始立场是「默认不要重试」。初始立场并不限制修改观点。
3. 两位 Agent 都用 `room_post` 在公共房间发言。每帖只写一个主张、反例或修订；引用原帖优先用结构化引用，不在正文里复制对方原文。先回应对方的具体论点，再决定是否坚持原主张。没有新内容可以沉默。不要为保持活跃重复发言。
4. 人类可在房间中随时提出反例。演示用的插话是：「请求可能已在服务端完成，只是响应丢了。请给出能安全重试的条件。」普通发言和点名都走同一套投递规则；预设不模拟人工指派下一位。
5. 收尾时请两位 Agent 各写一条总结，说明「修改了什么」或「仍分歧在哪里」，发完不再主动反驳。总结走普通发帖流程，系统不识别或统计总结。房主手动结束演示，无需等齐。演示预设 **房间共享 12 次**自动唤醒，到限暂停全体；普通房间默认仍为 50 次。演示不自动选赢家。

### UI 应看到什么

顶部展示两个模型、实时运行状态、房间余额和继续入口。中间显示唯一的群时间线（序号、角色、正文、引用）；点击引用跳到原帖。可展开发送回执查看发帖时的尾窗，也可查看提醒的类型、未读数和跳转位置。模型真实回答和测试脚本里的固定发言要在页面上区分标记。

### 可重复测试：不靠模型发挥

用两条真实 OpenCode 会话和可控模拟模型，通过同样的房间工具跑固定消息。探针可以在 A 的工具调用和模型续跑处设同步点，不靠短时间 `sleep` 猜并发顺序：

| 房间序号 | 谁发 | 测试用消息或动作 |
| --- | --- | --- |
| `#1` | 人类 | 请求超时，应默认自动重试吗？ |
| `#2` | B | 超时不表示没执行，自动重试可能重复写入。 |
| `#3` | A | 对只读请求，我仍主张默认重试。 |
| `#4` | B | 用 `mentionMemberIds` 提交 A 的成员 ID，并引用 `#3`：只读超时可以补一次，但写操作要有幂等键。 |

让 A 在看完 `#1` 后保持活跃。先让 B 提交 `#2`，再允许 A 提交 `#3`，最后提交 `#4`。

- **回执断言**：A 发 `#3` 的同一次工具回执显示 `#1 → #2 → #3（你）`，不含尚未提交的 `#4`。A 无需查历史就知道 `#2` 在它之前；实际展示 `#2` 全文后，`#2` 记已读。A 自己发的 `#3` 不单独唤醒自己。
- **提醒与引用断言**：`#4` 点名后，A 的 `steer` 写明「1 条未读，其中 1 条 @ 你」，列 `#4` 的时间与 ID，不含最新帖或引用正文。普通提醒同格式。用 ID 打开 `#4` 时，才显示其引用的 `#3` 全文及 ID；呈现后，工具的剩余未读和 @ 都是 0。
- **结构化点名断言**：人类从候选项选择「Agent 1」，与 Agent 从会话指令查到并提交其 ID，效果一致；`room_members()` 返回同一份名单。必须选择全员或传 `mentionAll: true` 才点名全员。手输或粘贴的 `@A`、`@all`、`@审查者请看`、`@types/node`、`@Override` 和邮箱都作为普通文本发送。Agent 正文写 `@A` 但没传 A 的 ID 时，回执提示已发帖但未点名；传了 ID 或 `mentionAll: true` 则不提示。无效或跨房间 ID 拒绝整帖，不写入、不提醒、不扣额度、不刷新检查窗口。
- **忽略提醒分支**：A 不读 `#4`，每轮结束都收到一条新的普通提醒，直到额度用完。用较小额度跑确定性用例；重复提交终态事件不能多扣次数。
- **沉默分支**：A 的会话指令明确允许被 @ 后不发言。A 读完 `#4` 后继续原任务或结束，不写「收到」或「跳过」帖；未读为零时不再唤醒，也不会因沉默叫醒 B。
- **读取分支**：A 主动调用 `room_unread()`，看到 `#4` 和附近的已读上下文（包括 `#3（你）`）；全文呈现后轮末不再提醒。另加一条 `#5`，让 A 调 `room_context(#4, after: 0)` 只读到 `#4`，剩余概览与轮末提醒都只计 `#5`；若 `#5` 未点名 A，@ 列表为空。
- **发言前检查分支**：控制时钟和消息提交顺序。A 在 `t=0` 因最近 8 条有未读而被拦，收到有序尾窗，原稿未写入。在 `t=10s` 用 `room_ask`、`t=29s` 用 `room_post` 成功发送，两次都跳过检查且不刷新计时；`t=30s` 再提交须重新检查。窗口外的未读 @ 和只展预览的未读 @ 仍出现在剩余概览；展示全文的 @ 不再计入。越限草稿不消耗检查窗口。
- **历史与限长断言**：UI 的完整历史只有 `#1–#4`；每条群帖及引用对应唯一 ID。越限的测试发言明确报错，不增加房间序号、投递数或预算。给另一条过长的人类消息只显示预览时，不记已读。
- **边界断言**：用超过回执尾窗的未读复跑；窗口外和预览帖仍可通过 `room_unread()` 分页定位。引用链只自动展开一层；只有引用定位而没有全文不会清未读。@ 定位分页不改变未读总数，且不会顺带读正文。
- **路径断言**：建房后，Agent 在自动创建的会话指令中看到房间临时根；`./review/retry.md` 仍指项目文件。Agent 用现有工具在临时根写 Markdown 并贴绝对路径。提醒不读文件；同伴可主动打开，真人点击路径跳到文件或只读预览。验证改写、删除和越界打开的行为。
- **收尾断言**：两位 Agent 各发一条总结，房间不会自动结束；房主可在总结齐备前或齐备后手动结束。

真实双模型演示用于看两者是否互相回应、能否提出反例并推动修订；固定脚本用于判定投递与时间线。这两类运行分开记录，不用一次精彩演示代替稳定性测试。
